# Add cross-project command support via --project flag

Enable running any tk command against a different project's tickets directory. Usage: tk [command] --project ~/code/project-name

## Design

File: ticket (single bash script ~2150 lines)

Approach: Parse --project <path> flag early in argument processing, before command dispatch.

Implementation:
1. Add --project flag parsing near top of script, before the case-statement dispatch (~line 2100+)
2. When --project is provided:
   - Validate the path exists and contains a .tickets/ directory
   - Override TICKETS_DIR to <path>/.tickets
   - Override the project prefix (currently derived from basename of pwd) to basename of the provided path
   - All subsequent command logic uses TICKETS_DIR and prefix as normal
3. Flag must be stripped from args before passing to command handlers
4. Works with every command since it just changes the directory context

Key code points:
- TICKETS_DIR is set at line ~15: TICKETS_DIR="${TICKETS_DIR:-.tickets}"
- ID prefix uses basename "$(pwd)" in generate_id() function
- Case-statement dispatch at bottom of script (~line 2100+)
- Need to handle both absolute paths and ~ expansion

## Acceptance Criteria

tk status --project ~/code/manager shows manager tickets. tk create 'test' --project ~/code/other creates ticket in other project. Invalid path (no .tickets/) prints error and exits 1.
